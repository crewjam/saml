API

A JSON API for creating and configuring test IdPs and SPs from scripts and test suites: everything the management pages do except logging in, which still happens in a browser.

There are no accounts or API keys. Creating an instance returns its secret, the same one that is in its management page's URL, and every other call names the instance by it: /api/v1/manage/{secret}. Keep it to yourself.

Instances made with the API are ordinary instances: they expire {{.Lifetime}} after they are created, and their manage_url opens them in a browser.

Quick start

Make an IdP, then an SP that trusts it. The IdP accepts the SP without registering it, by fetching its metadata from its entity ID.

curl -s -X POST {{$.BaseURL}}/api/v1/idps \
  -d '{"profile": "okta"}' | tee idp.json

IDP_METADATA=$(jq -r .metadata_url idp.json)

curl -s -X POST {{$.BaseURL}}/api/v1/sps \
  -d "{\"idp\": {\"metadata_url\": \"$IDP_METADATA\"}}" | tee sp.json

# Open the SP's login URL in a browser and log in as alice:
jq -r .sp.login_url sp.json

# Then read what happened:
curl -s "$(jq -r .api_url sp.json)/events" | jq '.[].title'

Request bodies are JSON. Content-Type is not checked, and an empty body is the same as {}. Unknown fields are refused, so a misspelt setting is an error.

Instances

POST /api/v1/idps

Creates an IdP with three users, alice, bob and carol. Optional: profile, one of {{range $i, $p := .Profiles}}{{if $i}}, {{end}}{{$p.Key}}{{end}} (the default is generic), and any IdP setting, applied after the profile.

{"profile": "entra", "name": "CI IdP", "remember_sessions": false}

POST /api/v1/sps

Creates an SP. Optional: idp, the IdP to trust, as {"metadata_url": …} or {"metadata_xml": …}, and any SP setting.

{"idp": {"metadata_url": "https://idp.example.com/metadata"}, "binding": "post"}

Both answer 201 Created with the instance, as GET /api/v1/manage/{secret} does, and its api_url in Location:

{
  "kind": "idp",
  "id": "comic-krill",
  "secret": "wholly-blessed-mammoth",
  "manage_url": "{{$.BaseURL}}/manage/wholly-blessed-mammoth",
  "api_url": "{{$.BaseURL}}/api/v1/manage/wholly-blessed-mammoth",
  "entity_id": "{{$.BaseURL}}/idp/comic-krill/metadata",
  "metadata_url": "{{$.BaseURL}}/idp/comic-krill/metadata",
  "certificate_url": "{{$.BaseURL}}/idp/comic-krill/certificate.pem",
  "certificate": "-----BEGIN CERTIFICATE-----\n…",
  "created_at": "2026-11-08T12:00:00Z",
  "expires_at": "2026-11-09T12:00:00Z",
  "idp": {
    "sso_url": "{{$.BaseURL}}/idp/comic-krill/sso",
    "slo_url": "{{$.BaseURL}}/idp/comic-krill/slo",
    "artifact_resolution_url": "{{$.BaseURL}}/idp/comic-krill/artifact",
    "settings": { "name": "Test IdP", "auto_fetch_sp_metadata": true, … },
    "profile": "generic",
    "users": [ … ],
    "service_providers": [ … ]
  }
}

An SP has sp instead of idp: acs_url, login_url, slo_url, artifact_resolution_url, settings, and idp (entity_id, metadata_url, metadata), which is null until it trusts one. A profile's entity ID is shaped like its product's, so an IdP's entity_id is not always its metadata_url.

PATCH /api/v1/manage/{secret}

Changes the IdP settings or SP settings in the body, and leaves the rest as they are. Answers with the instance.

curl -s -X PATCH {{$.BaseURL}}/api/v1/manage/$SECRET -d '{"allow_sha1": true}'

POST /api/v1/manage/{secret}/profile

Applies a profile to an IdP, {"profile": "shibboleth"}. Like "Behave like" on its page, this replaces its entity ID, users, signing and encryption settings: give its SPs the new metadata.

DELETE /api/v1/manage/{secret}

Deletes the instance, its sessions and its log now, rather than in {{.Lifetime}}. Answers 204 No Content.

Users

PUT /api/v1/manage/{secret}/users/{username}

Adds the user, or replaces the one with that username. nameid defaults to the username and nameid_format to unspecified. An attribute's name_format and friendly_name are optional. Answers with the user. An IdP has at most {{.MaxUsers}} users.

curl -s -X PUT {{$.BaseURL}}/api/v1/manage/$SECRET/users/dave -d '{
  "nameid": "dave@example.com",
  "nameid_format": "urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress",
  "attributes": [
    {"name": "email", "values": ["dave@example.com"]},
    {"name": "urn:oid:2.5.4.42", "friendly_name": "givenName",
     "name_format": "urn:oasis:names:tc:SAML:2.0:attrname-format:uri", "values": ["Dave"]},
    {"name": "groups", "values": ["admins", "users"]}
  ]
}'

NameID formats offered on the login page: {{range $i, $f := .Formats}}{{if $i}}, {{end}}{{$f}}{{end}}.

DELETE /api/v1/manage/{secret}/users/{username}

Removes the user. Answers with the instance, or 404 if there is no such user.

Service providers and IdPs

POST /api/v1/manage/{secret}/service-providers

Registers an SP with an IdP by its metadata, {"metadata_url": …} or {"metadata_xml": …}. An SP with the same entity ID is replaced. Answers with the registered SP. An IdP has at most {{.MaxSPs}}.

DELETE /api/v1/manage/{secret}/service-providers?entity_id=…

Removes a registered SP. Answers with the instance.

PUT /api/v1/manage/{secret}/idp

Sets the IdP an SP trusts, with the same body. Answers with the instance.

Metadata URLs of this server's own instances are read directly; others are fetched from public addresses only, on ports 80, 443, 8080 and 8443.

The SP's login_url takes the per-login options of its management page as query parameters, for links a test opens in a browser: binding, response_binding, force_authn=on, is_passive=on, authn_context and relay_state.

Log

GET /api/v1/manage/{secret}/events

The messages the instance exchanged, newest first: the last {{.MaxEvents}}. With ?after={id}, only those newer than that event, to poll for what a test just did. direction is in, out or empty; xml is the decoded message; url is its log entry page.

[
  {
    "id": 42,
    "at": "2026-11-08T12:03:11Z",
    "direction": "in",
    "ok": true,
    "title": "Logged in alice@example.com",
    "detail": "Subject: alice@example.com (emailAddress)\nIssuer: …",
    "xml": "<samlp:Response …",
    "url": "{{$.BaseURL}}/manage/wholly-blessed-mammoth/log/42"
  }
]

For a live feed, the management page's Server-Sent Events stream is at /manage/{secret}/live; it sends HTML fragments for the page.

DELETE /api/v1/manage/{secret}/events

Clears the log. Answers 204 No Content.

Errors

A request that fails is answered with a status and a JSON body. detail, when there is one, is the full chain of errors from the library.

{"error": "encryption must be one of auto, gcm, gcm128, cbc256, cbc, off, not \"aes\""}
StatusWhen
400The body is not valid JSON, has an unknown field or value, or the metadata cannot be fetched or read
404No such instance (it may have expired), user, SP or endpoint
409An IdP endpoint called on an SP or the reverse, or a limit on users or SPs is reached
503Too many instances exist on the server right now
